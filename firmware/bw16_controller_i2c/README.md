This is the isolated BW16 I2C variant for AmebaD 3.1.9. Existing UART 4.4 firmware remains in `../bw16_controller`; wrapper translation units reuse its controller, packet codec and radio implementation without editing those files.

The transport is I2C0 slave address 0x42: PA26/D8 SDA and PA25/D7 SCL. T-Embed uses GPIO8 SDA and GPIO18 SCL as its existing 100 kHz I2C bus. The connection requires common ground and 3.3 V signal pull-ups; it does not repurpose those pins as UART. GPIO43/44 remains dedicated to the NRF on the Plus. Confirm the exact carrier's exposed pads before wiring.

The local interrupt driver exchanges 64-byte frames and uses no Wire library, SDK slave task, busy waits, allocation, or radio calls in an interrupt. A write ends with STOP; a read ends with NACK+STOP. Write-to-read repeated START is supported. A full 64-byte read with an empty TX FIFO leaves the peripheral enabled immediately. Short/aborted reads flush stale bytes and re-arm through the main loop; the host must retry transient errors with a delay. Partial/oversize writes are discarded. A 100 ms transaction watchdog recovers abandoned transfers without blocking.

The protocol allocates one fixed BwiServer at setup from the SDK's reserved 250 KiB RTOS heap, before this adapter calls wifi_on. Its TX capacity stays 32768 bytes, with eight 40-byte command slots. A total-free-heap preflight includes the SDK block-header/alignment overhead. An obvious shortage skips allocation and returns FAULT after OPEN, without starting this adapter's Wi-Fi operations. The SDK allocator itself halts on OOM: a fragmented heap can therefore prevent startup even when aggregate free bytes pass the preflight. No transport allocation occurs in callbacks or during operations. Runtime heap availability with actual radio traffic still requires hardware validation.

OPEN resets controller state and old-session output. If an old asynchronous SDK scan is still in flight, READY stays low until its completion callback is discarded; a host opening too soon may need to retry. STOP bypasses the command queue, blocks further radio submissions immediately, then drains queued capture records before DONE. Normal capture export stays below 4096 bytes pending, preserving capacity for all eight queued records at STOP. Output overflow latches FAULT. Three seconds without valid host requests stops operations. Existing 30-second operation and 120-second capture deadlines remain independent of host polling.

Run `python tests/bw16_i2c_adapter/run.py` for the actual-adapter and actual-interrupt-driver harness with mocked hardware boundaries. On Windows set ZIG_CC to the installed zig.exe. It covers interrupted writes, all 63 short-read lengths, response retries, overflow recovery, reconnect/scan cleanup, zero-TX passive capture, STOP/capture deadlines and exact PCAP reconstruction. Tests and compilation are not physical hardware validation.

Build with `python tools/build_bw16_plus_i2c.py`. Only isolated build output is produced. This helper never opens a COM port. The shared-source wrapper includes require the original sketch directory in both C and C++ include paths when Arduino copies sources into its build directory.
