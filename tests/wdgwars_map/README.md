# WDGWars map API and test evidence

This directory tests the new standalone map app. It does not change or run the existing Wardriver.

## Endpoint evidence (2026-09-29)

Version 1.2 was also investigated using read-only authenticated GETs with the user's existing SD-card key. Private responses are kept under `.backups/wdgwars-live-diagnostics/` and must not be copied into fixtures or release archives. A local member viewport returned 5 cells / 2 hulls / 72 vertices with a 583-entry global gang dictionary. `/api/territories` returned a top-level array of 1,478 records / 465 unique gangs / 12,586 vertices, 677,539 bytes. Each record supplies `gang_id`, `name`, `color` and `[lat,lng]` hull vertices, plus ignorable metadata. Multiple hulls per gang remain separate. World member data was 3,894,269 bytes / 20,886 hulls, so zooms below 6 now use the dedicated overview route instead.

- Official public documentation: https://wdgwars.pl/press documents `GET /api/me`, `X-API-Key`, account counters and gang name. It lists a general limit of 120 requests/minute/key. The full map documentation at `/help` and map page at `/map` require login.
- Public client/source reference: https://github.com/Yggdrasil-AI-labs/wdgwars-api-tester/blob/main/wdgwars_api_tester.py describes `GET /api/member-territories?compact=1&bbox=W,S,E,N&zoom=Z`. Its notes describe an echoed `[S,W,N,E]` bbox, `cells`, `gang_hulls`, a compact `gangs` dictionary, five-minute snapshots, and low-zoom cell omission. This is a third-party client's implementation evidence, not WDGWars server source.
- An unauthenticated GET of `/api/member-territories?compact=1&bbox=-74,40,-73,41&zoom=8` returned HTTP 401 with `Missing or invalid API key`. That initial unauthenticated probe used no account key and read no account data. The later authenticated GET investigation is described above; no uploads were sent.
- The sample geometry at https://github.com/Yggdrasil-AI-labs/wdgwars-api-tester/blob/main/mock_wdgwars.py is a **mock fixture**, not a verified response from the user's account. Tests use similarly synthetic, deliberately small fixtures.

The parser accepts the verified scalar-grid/compact-gang/hull shape and the dedicated top-level overview array. Compact gang lookup is delayed until geometry is known, then only referenced teams are retained. Unknown JSON fields are skipped with bounded depth and strict JSON/UTF-8 validation. Required fields, duplicate known keys, ranges, array sizes, colors and geometry are checked. Malformed/unsupported responses preserve the displayed/saved snapshot. It does not silently replace a map with an empty result after a schema failure.

The cell `lat`/`lng` anchor convention has not been verified against authenticated documentation. Consequently the parser leaves `cell_anchor=Unknown`: cells can be shown as location markers, but no invented cell boundaries are drawn. Returned hull coordinates can be drawn directly. Source generation time is unknown unless a supported future schema supplies it; `downloaded_at` is the local, separately supplied fetch time, never a fabricated server timestamp. Authenticated territory responses have been checked on the host; physical version 1.2 testing remains pending.

## Bounds and ownership

WDGWars response limit: 1 MiB; map maximum: 1,024 cells, 1,024 gang entries, 2,048 hulls, 32,768 hull vertices. Overpass keeps its independent 512 KiB limit. Account response limit: 32 KiB. Strings are length bounded, valid UTF-8, and sanitized for display; the shared truncated string reader preserves a complete UTF-8 prefix. Allocation failure or oversized areas return a useful error while retaining old data. Territory geometry does not identify physical Wi-Fi/BLE ranges or determine ownership from local scans.

JSON parse commits atomically to the caller's output only on success. The HTTP helper accepts allowlisted GET paths and two fixed HTTPS origins: WDGWars and the selected public Overpass instance. A WDG key is required only for WDGWars and rejected for Overpass. TLS hostname/certificate validation is enabled, redirects disabled, and the established WLAN worker/connection reused. The HTTP helper has no automatic retries, scans, uploads, new Wi-Fi ownership, or embedded browser code. Requests have a 60-second overall deadline, with 25-second Overpass I/O (the query itself allows 20 seconds) and 10-second WDGWars I/O. Cancellation may wait for the current I/O call. The app enforces refresh/backoff scheduling. Numeric Retry-After values are bounded to a day; unsupported date-form values conservatively request a one-day backoff. HTTP completion is explicitly checked, including chunk framing.

## Run locally

- `python tests/wdgwars_map/run_parser.py`: compact/expanded cells and gang lookup, geometry, truncation, malformed numbers, invalid UTF-8/escapes, duplicate keys, oversize arrays, account parsing and output preservation.
- `python tests/wdgwars_map/client_integration_run.py`: production basemap fetch/query -> production HTTP client -> mocked ESP-IDF transport -> production parser; all supported zoom routes, service authentication isolation, delayed headers, HTTP errors, explicit empty results, partial chunk rejection, public captured-response replay and documented low-zoom WDG hull shape. This does not claim live authenticated WDGWars verification.
- `python tests/wdgwars_map/run_client.py`: mocked verified TLS and GET configuration; origin/key separation; 401/429/redirects; cancellation and deadlines; response limits, incomplete reads/chunks, old-map preservation.
- `python tests/wdgwars_map/app_run.py`: actual application helper bodies extracted from the production source, with narrow hardware mocks; tests cold startup and GPS versus saved-area priority, account-only and empty caches, sequential roads/territory loads, independent service cooldowns, explicit refresh with automatic loading disabled, once-per-view automatic loading, movement during a request, whole-world and dateline overview bounds, saved zoom zero, coordinate editing, GPS stop/reset and saved configuration reuse, menu input, allocation failure, worker join/snapshot swap, save rejection without geometry, cancellation around saves, and 64-bit retry deadlines.
- `python tests/wdgwars_map/cache_run.py`: CRC/version/size/geometry validation, backup recovery, invalid/truncated/appended data, write/open/sync/close/rename/remove failures and transient read faults. Asserts every attempted file open is closed and storage references/allocations are released.

All fixtures and transport/storage fault injection are local. Linux builds enable ASan/UBSan; Windows uses the repository's Zig host-test wrapper with assertions enabled.
